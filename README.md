# DE-Rigor-Agent

DE-Rigor-Agent is an AI agent for bulk RNA-seq differential expression (DE)
analysis driven by natural-language requests. Given an expression matrix,
sample metadata, and a description of the comparison, it:

1. **Cleans the data**: inspects the uploaded files, aligns samples with
   metadata, and writes standardized `expression.csv` and `metadata.csv`.
2. **Filters DE methods**: checks the data against the statistical assumptions
   of each candidate method and proposes the suitable ones for approval.
3. **Runs the analysis**: executes the approved methods through specialized
   sub-agents, compares their results, and reports findings with plots and the
   full code record.

Supported DE methods: Wilcoxon rank-sum test, DESeq2, edgeR, limma-voom,
limma without voom, and NOISeq.

The project provides a Chainlit browser interface and a terminal CLI. Both run
the same agent and execute generated Python and R code on the local machine.

## Requirements

- Python 3.13 or later and [`uv`](https://docs.astral.sh/uv/).
- An OpenAI API key, set as `OPENAI_API_KEY` in the environment or in a `.env`
  file in this directory.
- R with `Rscript` on `PATH`, with the packages `tidyverse`, `DESeq2`, `edgeR`,
  `limma`, and `NOISeq` installed.

## Installation

Run all commands from this directory (the one containing `app.py` and `cli.py`).

```bash
uv sync
```

This creates `.venv` with the Python dependencies. Python snippets generated by
the agent run with this interpreter; R snippets run with `Rscript` from `PATH`.
To use an R installation outside `PATH`, prepend its binary directory before
starting either interface:

```bash
export PATH="/path/to/r/bin:$PATH"
```

## Browser interface

```bash
.venv/bin/chainlit run app.py --headless
```

Open the URL printed in the terminal. Attach the expression data and sample
metadata to your first message together with the analysis request, for
example "Compare disease versus control, adjusting for batch." The agent will
ask for approval of the proposed DE methods before running them and may ask
clarifying questions. If no files are attached, the agent answers the message
directly without starting the DE workflow.

The model can be changed in the chat settings; the default is
`openai/GPT-6 Luna`.

Each chat session works in `agent_web_runs/<timestamp>_<UUID>/` under this
directory. Session files remain on disk after the chat ends.

The **Download** command exports the conversation as `chat_history.json` and
`chat_history.html`. The HTML can be opened offline. These exports contain the
chat text and recorded code execution but not the uploaded files, generated
files, or images, which stay in the session working directory.

## Terminal CLI

```bash
.venv/bin/python cli.py \
  --message "Compare disease and control samples." \
  --input path/to/counts.csv \
  --input path/to/metadata.csv
```

| Parameter | Meaning |
| --- | --- |
| `--message TEXT` | Analysis request. Supply exactly one of `--message` and `--message-file`. |
| `--message-file PATH` | Read the request from a UTF-8 text file. |
| `--input PATH` | Input file to copy into the working directory. Repeat for multiple files; filenames must be unique. At least one file is needed to start the DE workflow. |
| `--model ID` | `gpt-6-luna` (default), `gpt-5.6-luna`, `gpt-5.6-sol`, or `gpt-5.6-terra`. |
| `--run-dir PATH` | New run directory for `run.md` and `working/`. Must not already exist. |
| `--interactive` | Answer agent questions and approve DE methods in the terminal. |
| `-h`, `--help` | Show command-line usage. |

By default the CLI runs without terminal interaction: it automatically
approves the proposed methods and, when the agent asks a question, instructs it
to proceed with reasonable assumptions.

Without `--run-dir`, the run directory is
`agent_cli_runs/<timestamp>_<UUID prefix>/` under this directory. The CLI
writes a Markdown log of the whole run (prompts, reasoning summaries, executed
code with output, generated files, and token usage) to `<run-dir>/run.md` and
executes code in `<run-dir>/working/`. Both paths are printed when the run
finishes.

## Working directory layout

Both interfaces create these subdirectories inside the code working directory:

| Directory | Contents |
| --- | --- |
| `uploads/` | Copies of input files. |
| `data/` | Cleaned analysis data (`expression.csv`, `metadata.csv`). |
| `results/` | Final DE tables and plots. |
| `intermediate/` | Intermediate files and exploratory plots. |

Each code snippet runs in a separate process with a 600-second time limit, and
its captured output is truncated to 2000 characters. Files persist between
snippets; variables and imports do not.

## Project layout

| File | Purpose |
| --- | --- |
| `agent.py` | Core agent: LangGraph workflow, tools, and DE sub-agents. |
| `app.py` | Chainlit browser interface. |
| `cli.py` | Terminal CLI and Markdown run log. |
| `prompts/` | Prompt templates for each workflow step and DE method. |
